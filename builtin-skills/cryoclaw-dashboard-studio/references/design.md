# Composition and motion

Use CryoClaw's ice blue, ink and paper with clear Chinese typography. Prefer a strong headline, one visual idea and quiet metadata. Keep source, data time, loading and failure feedback readable. Design a useful empty state. Avoid decorating every surface or copying another product's branding.

The board uses a fluid 12-unit wrapping layout with 20 px gaps. Widths accept fractional units for continuous resizing; height is in pixels. Manually resized cards keep their chosen width (`layout.free: true`), while templates reflow responsively. Arrange preserves reading order and section anchors, balances row widths/heights and offers layout undo. Narrow workspaces give small cards at least six columns, then stack every card below 680 px. Each iframe receives its actual card width and height: use responsive CSS, flex/grid, clamp() and media queries instead of a fixed design surface. In editing mode the 36 px chrome reserves space above content; expansion keeps the same running document and fills the window below a 44 px chrome. Test small, wide, short and expanded sizes. Allow internal scrolling when content cannot fit; keep controls readable rather than shrinking the whole interface.

Motion may be sparse but must be fluent, natural and useful. Normal mode keeps the complete motion language; never remove animation merely to claim a performance win. Preserve the same element/state during transition. Reverse from its current visual position when interrupted; avoid flashing back or restarting timers. Prefer transform/opacity and short purposeful transitions. Keep ambient movement weak enough for reading. Use `sdk.motion.frame(draw,{fps:30})` for continuous work and `sdk.motion.animate(element,keyframes,options)` for one-shot transitions; both pause hidden work and honor the user's explicit reduced-motion preference. Controls must still work in that mode. Never animate through repeated publishing or storage writes. Resize Canvas only on size/DPR changes, cap DPR at two, and limit drawing frequency.

Load state before enabling edits, debounce persistence, and show failures. Use deadlines for timers, not a write per second. Play real audio only after a user action; label generated sound honestly and derive any spectrum from the actual audio analyser. Keep public data provenance visible. Offer follow-up ideas through `sdk.compose(prompt)` and task setup through `sdk.tasks()`; both require a click in the main window and neither sends a message automatically. The quick-notes pattern shows local persistence plus an optional action-plan draft. Use the card chrome refresh action for a single document; the board toolbar is for the whole board. The board header presents current metadata, so avoid repeating board-level identity inside every card.

Before delivery check: initial/loading/empty/error states; rapid reverse/repeated actions; keyboard focus and Escape; narrow responsive view; reduced motion; hide/resume; refresh restoring state; no unsolicited audio; no per-frame layout, bitmap allocation, network or model work. Read one card and update its stable ID; preserve user geometry and other modules.
