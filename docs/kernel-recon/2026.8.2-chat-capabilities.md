## A. 流式文本协议

### A.1 chat delta 载荷【dist 确证：dist/server-chat-DZFFhPUJ.js】

发送端 `resolveBroadcastDelta()`：

    function resolveBroadcastDelta(params) {
      const previous = params.previousBroadcastText;
      if (previous === void 0) return params.text ? { deltaText: params.text } : void 0;
      if (!params.text.startsWith(previous)) return { deltaText: params.text, replace: true };
      const deltaText = params.text.slice(previous.length);
      return deltaText ? { deltaText } : void 0;
    }

delta 事件完整载荷：

    {
      runId, sessionKey, agentId?, spawnedBy?,  // spawnedBy = 子代理来源
      seq,                        // 每 run 单调递增
      state: "delta",
      deltaText,                  // 纯增量（相对上次广播文本的前缀差）
      replace?: true,             // 新文本不再是旧文本前缀扩展时置位；deltaText 此时为全量替换
      message: { role:"assistant", content:[{type:"text", text: <全量累计>}], timestamp }
    }

语义确证：deltaText 是纯增量；全量文本始终随 message 附带作为校验/兜底；replace 处理“改写/回退”场景。重连对齐不走 deltaText，走 chat.history cursor（A.4）。

### A.2 终态事件【dist 确证：dist/chat-send-handler-8cDg2Jl1.js broadcastChatTerminal】

- `state:"final"`：`{runId, sessionKey, agentId?, seq, state, message: projectChatDisplayMessage(...), stopReason?}`
- `state:"aborted"`：runtimeCancelled 时与 final 同构
- `state:"error"`：`{..., errorMessage, stopReason?, errorKind?}`
- 另有 `chat.side_result` 广播（btw 副结果：payload 含 `btw.question` + `text`）
- `chat.inject` 注入消息也发 `state:"final"`（runId=`inject-<messageId>`, seq:0）

### A.3 control-ui 官方 deltaText 消费逻辑【dist 确证：control-ui-boot-BgFR4nR0.js 函数 DT】

    function DT(currentText, payload){
      const full = payload.message==null ? null : Gr(payload.message);
      if (typeof payload.deltaText == "string"){
        if (payload.replace === true) return payload.deltaText;         // 全量替换
        if (currentText === null) return full ?? payload.deltaText;
        if (typeof full == "string"){
          const r = full.length - payload.deltaText.length;
          if (r !== currentText.length || full.slice(0,r) !== currentText) return full; // 校验失败回退全量
        }
        return currentText + payload.deltaText;                          // 追加增量
      }
      return full ?? null;
    }

官方做法 = 增量追加 + 全量交叉校验 + replace 分支。CryoClaw 可直接照抄此合并函数。

### A.4 乱序/断连保护【dist 确证】

- 网关对每 runId 记录 seq；`evt.seq !== last+1` 时先 flush 缓冲，再向 control-ui 广播 `agent` 事件 `stream:"error"`，`data:{reason:"seq gap", expected, received}`（server-chat）。
- assistant/thinking 文本流网关侧缓冲+节流合并：`AGENT_TEXT_THROTTLE_STREAMS = ["assistant","thinking"]`，flush 前按 seq 排序。
- 重连增量同步：`chat.history` 支持 `cursor` 参数（与 offset/messageId 互斥），返回 `{kind:"delta"|"reset", deltaCursor, messages, activeLeafEntryId}`（chat-CESxHe7C.js readChatHistoryDelta）；transcript 遇 reset/compaction 断点返回 `kind:"reset"` 要求全量重载。control-ui 持久化每会话 deltaCursor，重连用 `cursor:` 拉增量。
- `chat.startup` = 新会话启动版 history（同 handler；readPolicy "current" vs history 的 "ready"），返回 sessionInfo/metadata/inFlightRun/activeRunIds/pendingInputs。

### A.5 thinking/reasoning 流【dist 确证：builtin-openclaw-DSKrNRlA.js】

agent 事件 `stream:"thinking"`，data 为 `{text: <全量累计>, delta: <增量>}` 双字段（与 chat delta 同构但字段名不同）。配置 `agents.defaults.reasoningDefault: "off"|"on"|"stream"`（zod-schema-DaszE3SW.js 确证）。

## B. 工具调用流式输出

### B.1 agent tool 事件形态【dist 确证：生产端 builtin-openclaw / run-attempt-B8rKAjux；消费端 control-ui-boot-BgIRudBT.js】

`stream:"tool"`，`data.phase` 取值：

| phase | 字段 | 说明 |
|---|---|---|
| `start` | `name, toolCallId, args, meta?, commandBearing?, hideFromChannelProgress?` | 调用开始，args 已 sanitize |
| `update` | `name, toolCallId, partialResult` | 执行中部分结果，250ms 节流（LIVE_EXEC_UPDATE_MIN_INTERVAL_MS=250） |
| `input_delta` | `toolCallId, name, diff:{added, removed}` | 文件改写工具流式参数期间实时 diff 行数（embedded-agent-live-edit-diff；250ms 节流、partialJson>1MB 停跟踪、最多 64 并发 call） |
| `result` | `name, toolCallId, meta?, isError, commandBearing?, result, toolErrorSummary?, hideFromChannelProgress?` | 终态 |
| `review` | `review` | 审批复核（control-ui 消费端确认） |

工具级进度上报：tool result 可携带结构化 `progress:{visibility:"channel", privacy:"public", text}`（readChannelToolProgress）——工具可主动上报阶段文本；channel 投影消费它，WS 客户端在 partialResult 原始数据里也能拿到。

截断（内核侧，dist/embedded-agent-tool-results-DGHTfGuE.js）：
- TOOL_RESULT_MAX_CHARS = 8000，尾部追加 `…(truncated)…`
- LIVE_EXEC_OUTPUT_MAX_CHARS = 8000，尾部 `...(live output truncated)...`（capLiveExecResult 处理 exec 聚合输出）
- TOOL_ERROR_MAX_CHARS = 400

分发规则【dist 确证 server-chat】：control-ui 连接（isControlUiVisible）永远收到完整 agentPayload（含 result/partialResult）；只有 channel 客户端在 verbose≠"full" 时被剥掉 result/partialResult（channelToolPayload 分支）。CryoClaw 作为 WS 客户端收到的就是全量。

### B.2 toolProgressDetail【dist 确证 zod-schema + 文档 docs/gateway/config-agents.md:422】

## C. Progress Card（进度卡片）

### C.1 内核一等能力【dist 确证】

- RPC：`progressCard.get` / `progressCard.put`（method-scopes 注册表确证；实现 dist/progress-card-B2ysEcjM.js）
- `put` 支持 `expectedRevision` 乐观锁；清空（dismiss）必须带 expectedRevision
- 存储：sqlite 表 `session_progress_cards`（session_key, markdown, steps_json, revision, created_at, updated_at），每会话一卡
- 广播事件：`progressCard.changed` `{sessionKey, revision}`（无 expectedRevision 写入或卡片被清空时广播）
- 卡片模型（progress-card-input-Cwbo_Miv.js normalizeProgressCardInput，replace-on-write）：
  - `markdown?` string ≤ 8192 UTF-8 字节（stripInvisibleUnicode 清洗）
  - `plan?` ≤ 50 步，每步 `{step: string ≤512B, status: "pending"|"in_progress"|"completed"}`，至多 1 个 in_progress
- Agent 侧另有 `progress_card` 工具（run-attempt：tool.result 成功后 recordDynamicProgressCardUpdate + compactionPlanState.recordProgressCardInput；工具注册表 `progress_card -> "Progress Card"`）

### C.2 control-ui 渲染【dist 确证】

- store（D1UIyDYT）：按 gateway client WeakMap 缓存；watch(sessionKey) → `progressCard.get` 拉取 + 订阅 `progressCard.changed` 失效重拉；dismiss → `progressCard.put`（带 expectedRevision 清空）
- Chat 页挂在 composer 上方浮动卡（CGa0vjXT：`agent-chat__progress-float`），入参：`collapseTaskProgress`（设置 settings.chatCollapseTaskProgress）、`progressCardHasActiveRun`、`onDismissProgressCard`
- 渲染细节（D1UIyDYT 渲染器）：markdown 体（progressBars 增强）+ steps 有序列表；in_progress=spinner、completed=✓、pending=🕐；无活跃 run 时 in_progress 降级显示 "paused"；`{completed}/{total}` 计数；全部完成时显示 dismiss 按钮；带 updatedAt/startedAt/endedAt 与 run 结果（done/failed/timeout/killed）
- 看板 widget：`openclaw-session-progress-widget`（session-progress-DIzCJ_7O.js）复用同一渲染函数

### C.3 "session startup progress"（PR #133489）的真实形态【dist 确证 + CHANGELOG 宣称】

不是卡片，而是 chat 事件新状态 `state:"status"`：

    // server-chat：由 agent 事件 stream:"run_status" 投影，controlUiVisible 且 dropIfSlow

phase 枚举（readChatRunStartupPhase）：`preparing_workspace | naming_worktree | creating_worktree | running_setup | provisioning_environment | preparing_context | starting_model`。

control-ui 映射为 chat pane 状态行文案（chat.startupStatus.* 系列：provisioningEnvironment/preparingWorkspace/creatingWorktree/runningSetup/preparingContext/startingModel），存于 `chatRunStartup`。PR #133489 修的是“进度反复命名/回退”。

### C.4 长任务/子代理/cron 进度【dist 确证】

## D. control-ui 工具结果渲染管线

### D.1 合成消息管线【dist 确证 control-ui-boot-BgIRudBT.js】

- 每 toolCallId 维护 `{toolCallId, runId, sessionKey, name, args, output, details, isError, exitCode, liveDiffStat, resultReceived, startedAt, receivedAt}`
- 合成 message 带内部标记：`__openclawToolStreamLive / __openclawToolStreamResultReceived / __openclawToolStreamDiffStat / __openclawToolStreamReceivedAt`

- start 且属当前 run 时置会话为 activity 状态；`session_status` 工具的 result 单独投影

### D.2 调用/结果配对【dist 确证 control-ui-boot-BgFR4nR0.js】

### D.3 富渲染与折叠【dist 确证】

- 工具显示注册表（CcqoIT0C，63 条 `{emoji, title, detailKeys[], actions?}`），覆盖：bash/exec/process/terminal/computer/portal、read/write/edit/apply_patch/attach、web_search/web_fetch、browser、image/view_image/image_generate/music_generate/video_generate、pdf、cron、sessions(_list/_send/_history/_search/_spawn)/subagents/agents_wait/agents_list、memory_search/memory_get、message、canvas/dashboard/nodes、progress_card、ask_user、secrets、suggest_task/dismiss_task、code_execution、structured_output、tool_call/tool_call_update（动态工具）、session_status、github_publish、tts 等
- diff 富渲染（D1UIyDYT）：edit/write 结果 details 的 diff 文本解析为 `{kind:"add"|"del"|"ctx"|"skip", lineNo, text}`（上限 400 行截断），统计 added/removed；独立 chunk `chat-diff-highlight.runtime-Pfs9etoA.js` 做高亮；结果到达前用 input_delta 的 liveDiffStat 显示实时 +a/-r

- isError：result.isError 布尔直接进卡片状态；另有 toolErrorSummary、exitCode
