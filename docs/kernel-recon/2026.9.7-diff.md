# OpenClaw 2026.9.3 → 2026.9.7 差异取证（只读，不改内核）

> 方法：npm 下载两版 tarball 解包（`.cache/kernel-recon` / 临时目录）做 registry/结构/关键函数比对；
> 补丁命中经真实 `npm run package:resources` 安装树（openclaw@2026.9.7 + fs-safe 0.21.1）实跑验证；
> asar 形态经 `scripts/gateway-asar-smoke.test.js` 真实启动冒烟（Electron-as-Node）。
> 结论先行：**RPC 面一减一增（sessions.compaction.\* 移除 → sessions.branches.list/switch + sessions.rewind/fork
> 树模型替代，CryoClaw UI 已同步重建为「分支」体系）；渠道插件 schema 收紧（qqbot 不再随内核分发、
> telegram 令牌字段 token→botToken）；fs-safe 0.8.5→0.21.1（pinned-open realPath 声明改形，补丁已适配）；
> 其余（engines、entry.js、dist/extensions 目录、compaction 标记、manifest-scan 缺口）形态不变或纯增量。**

## 1. 运行环境（无变化）

- Node engine：`>=24.16.0 <25 || >=26.1.0`（与 2026.9.3 相同）；`cryoclaw.node: 24.21.0` 满足，无需调整。
- dist 根 chunk 维持 `.mjs` 主导（v9.7：7113 `.mjs` + 1932 `.js`），`dist/entry.js` 仍在
  （package-resources install-skip 与 updater 校验不受影响）；R72 的 `.mjs` 扫描覆盖继续有效。

## 2. Gateway RPC 面（Breaking — 会话回放/分支体系重构）

- `sessions.compaction.{list,restore,branch}` **移除**（v9.3 asar 内 35 处引用 → v9.7 dist 零命中）。
  内核仅存 `legacy-compaction-history`（读旧 checkpoint 快照路径，用于归档维护；**不迁移**为分支）。
- 替代 RPC（树模型，transcript 为一棵树，可见历史 = active path）：
  - `sessions.branches.list {sessionKey}` → `{branches:[{leafEntryId, headline, messageCount, updatedAt?, active}]}`；
  - `sessions.branches.switch {sessionKey, leafEntryId}` → `{}`（leaf 必须是树上 tip；活跃 run / 归档 / 外部接管时拒）；
  - `sessions.rewind {sessionKey, entryId}` → `{editorText?, editorAttachments?}`（entryId 必须是 active path 上的
    **用户消息**；把该消息及其之后移出 active path（保留为分支，非破坏），消息文本/内联图片回填输入框）；
  - `sessions.fork {sessionKey, entryId}` → `{sessionKey(新), editorText?, editorAttachments?}`（prefix 截止到该消息之前）。
  - 活跃 run 中操作一律 UNAVAILABLE（"unavailable while the agent is working"）。
- `chat.history` 响应新增 `activeLeafEntryId`（增量字段，旧调用方不受影响）。
- **CryoClaw 适配**：chat-ui 移除旧 compaction checkpoint popover（依赖已删除的 RPC），
  新建 `controllers/session-branches.ts` + 输入框「分支」popover（branches.list/switch）
  + 用户消息气泡「回退编辑 / 分叉新会话」入口（rewind/fork），语义见控制器头注。

## 3. 渠道插件（Breaking — schema 收紧，影响冒烟夹具与配置写入方）

- `channels.qqbot`：**qqbot 不再随内核 dist/extensions 分发**（9.7 内置渠道仅 telegram 等核心家族）；
  CryoClaw 经 extensions-mirror 继续供应 qqbot/wecom/weixin/dingtalk 插件，真实 App 不受影响，
  但裸 asar/裸安装树下 qqbot 配置即 unknown channel。
- `channels.telegram`：`token` 字段被 schema 拒绝（`must not have additional properties: "token"`，
  实测复现），改用 **`botToken`**（或 `tokenFile` / `TELEGRAM_BOT_TOKEN` env）；
  实测 `channels.telegram.{enabled, botToken, allowFrom:["*"]}` 可正常启动。
- 泛化教训：渠道配置由**插件 schema** 校验，且插件 schema 在启动第二阶段才参与快照校验——
  第一阶段（core-only）放行的旧形状会在 recheck 阶段报 `config validity changed` 拒绝启动
  （`scripts/gateway-asar-smoke.test.js` 夹具已随此结论修正为 telegram+botToken）。

## 4. @openclaw/fs-safe 0.8.5 → 0.21.1（补丁适配）

- `patchAsarBoundaryCheck` 六注入点：root-file/pinned-open/regular-file/file-identity 文件形态不变，
  真实安装树实跑命中 **7 模块**，`assertAsarBoundaryCoverage` PASS。
- `patchFsSafeAsarUnpacked`（asar 身份观测映射）：0.21.1 `pinned-open.js` 的 `realPath` 声明改形
  （`params.` 解构为局部变量 + 双路 realpath：`ioFs === fs ? realpathSync(filePath) : ioFs.realpathSync(filePath)`），
  旧 marker 未命中导致补丁静默跳过（首次打包日志「跳过（形态未命中）」）——
  **已适配**（`origDeclV21` 双形态兼容 + kernel-dist-patch.test.js v21 fixture），重跑后「已注入」。
- 身份观测点本体（两次 `lstatSync(realPath, {bigint:true})`）两版逐字节同形态，补丁策略不变。

## 6. Agent DB schema 门槛（Breaking — 存量用户升级死锁，CryoClaw 已自动化）

- 2026.9.7 的 agent DB 准入（`assertCanonicalAgentPersistenceVersion`）：`userVersion < 24`
  即拒绝（exit 78，"uses schema version 19; … run openclaw doctor --fix to migrate session
  identities"）；2026.9.3 的同款门槛是 19。**升级 App 后首启必触发**，迁移唯一入口是
  `openclaw doctor --fix`（配 `--non-interactive` = safe migrations only）。
- **迁移死锁（上游缺陷，本机实测复现）**：网关每次启动先在 state 库
  `agent_database_leases` 写租约再撞 schema 门退出，exit 78 不清租约 → 租约累积
  （本机 229 条）；doctor 的租约准入 `isAgentDatabaseLeaseStale` 在「pid 被其他进程
  复用」且「启动时间读不到」时保守判活跃——被 svchost 复用（kill(0) 报 EPERM）的
  3 周前死租约永久阻塞 doctor（"Agent main database is still open in process 6000"）。
- **CryoClaw 适配（src/agent-db-migration.ts，gateway doStart 预启动段接线）**：
  检测（sqlite 头偏移 60 直读 user_version，零依赖）→ 清失效租约（ESRCH/EPERM 判
  陈旧，可信号存活进程保守保留）→ `doctor --fix --non-interactive`（10min 超时）→
  复检。会话级单次、失败只记日志（走既有失败弹窗）。真机验证：229 条租约清 228 条
  → doctor 迁移完成（userVersion 19 → 24）→ 网关正常启动。
- **回退约束**：迁移后的 DB（24）对 2026.9.3 内核不可用（`>19` 即拒）——App 与内核
  同版分发，正常路径不触发；内核-only 更新通道由 kernel-update.mjs 的换装失败回滚兜底。
