# OpenClaw 2026.8.2 → 2026.9.2 差异取证（只读，不改内核）

> 方法：npm 下载两版 tarball 解包（`Temp/kernel-recon/v8|v9`），对 dist 做 registry/结构/关键函数比对；
> CLI 矩阵经 wrapper 实测（`scripts/cli-compat-smoke.js --kernel-entry`）。
> 结论先行：**协议层纯增量（RPC +40 / -0），chat delta 语义逐字节一致，扩展目录布局不变**——
> CryoClaw 侧升级风险集中在 Node engine 门槛与 CLI 命令树收缩，UI 侧新能力走特性探测即可兼容双内核。

## 1. 运行环境

| 项 | 2026.8.2 | 2026.9.2 | 影响 |
|---|---|---|---|
| Node engine | 无此硬门槛 | **≥22.22.3 <23 \| ≥24.15.0 <25 \| ≥25.9.0**（preinstall 守卫实测拒绝 24.14.0） | 系统 Node 24.14.0 直接跑 v9 入口失败；**Electron 43.4 自带 Node 24.18.1 实测可跑**（ASAR 形态不受影响；散文件 dev 模式需升系统 Node 或走 Electron） |

## 2. CLI 命令树（实测矩阵）

- 顶层命令 70 个；全部一级子命令 `--help` 退出码 0（交互式 7 个跳过：chat/tui/configure/dashboard/attach/connect/completion）。
- **新增**：`wiki`
- **移除**：`browser`、`file-transfer`、`googlemeet`、`teamsmeetings`、`zoommeetings`
- 注意：`browser` 扩展本体与 `browser.*` RPC **保留**，仅 CLI 入口收敛——CryoClaw 的 browser 通道不受影响。

## 3. Gateway RPC 注册表（method-scopes-*.js）

- v8 384 → v9 **424（+40 / -0，纯增量）**。
- 新增清单（按域分组）：
  - **transcripts**：`transcripts.list`、`transcripts.get`（会话记录复制/导出的内核支撑）
  - **skills.library**：`activate/import/list/mutate/read/save/upload`（技能库管理）
  - **plugins.controlUi**：`list/reload/report/status`（插件自带 Control UI 面板）
  - **mentions**：`mentions.list`、`mentions.dismiss`（未读/@ 提及）
  - **users**：`github.authorize.start/poll/cancel`、`github.disconnect/status`、`authConnect.start/answer/cancel/catalog/status`、`linkAuthProfile/unlinkAuthProfile/listAuthLinks`、`listModelAccounts/selectModelAccount`、`mentionable`
  - **sessions**：`github.confirm/options/status`、`title.prepare`
  - **升级/恢复**：`update.runs.get/list`、`gateway.suspend.handoff`（Gateway 挂起移交——重启恢复链路）
  - **models**：`models.authOrderSet`
  - **canvas**：`canvas.document.view`

## 4. chat 流协议

- `resolveBroadcastDelta`（server-chat）**两版逐字节一致**：首帧/倒退帧 `{deltaText: 全文, replace:true}`，append 帧后缀。
- v9 新增 `mergeAgentTextPayload`（agent 文本合并，配合 suspend/handoff 的重启恢复）。
- CryoClaw `chat-stream-reducer` 语义无需变更。

## 5. progressCard

- 契约不变（revision/steps/clear/markdown 全保留，文件大小 8800→8792 字节级差异）。R52 的 Progress Card 适配继续有效。

## 6. 模型目录

- v9 catalog 新增 **gpt-6-astra**：reasoning、input text+image、contextWindow 1.05M、contextTokens 272k、maxTokens 128k、tiered 计价（10/50/1/12.5）。
- CryoClaw 模型页读内核动态目录，无需代码变更（能力徽标随 catalog 自适应）。

## 7. 扩展目录布局

- `dist/extensions/` 两版目录列表 **完全一致**（diff 为空）；manifest 路径不变。
- 打包白名单（`OPENCLAW_EXTENSION_ALLOWLIST`）、updater `carryOverInjected`（skills/ + dist/extensions/）无需调整。

## 8. 升级闸门结论（对应计划的适配清单）

| 检查面 | 结论 |
|---|---|
| Gateway RPC | 纯增量，旧调用全兼容 |
| WebSocket hello/connect | client 侧工具代码一致；suspend.handoff 为新增可选流 |
| chat 事件 | 语义不变 |
| agent/tool 事件 | 无破坏性差异（registry 无移除） |
| sessions/history | 参数面兼容（includeDerivedTitles 两版都在） |
| config.get/patch | 未观察到契约变化 |
| plugin manifest/加载入口 | 布局不变 |
| browser/profile API | RPC 保留（仅 CLI 命令收敛） |
| remote-control API | 无移除；users.authConnect 为新增 |
| CLI 命令树 | +wiki / -5 个；wrapper 透传不受影响 |
| 自动升级/配置恢复/Gateway 重启恢复 | update.runs.*、suspend.handoff 为新能力，接入属增强项 |
| GPT-6 Astra | 动态 catalog 自适应，无代码变更 |

**判定**：协议/布局层面无阻断项；2026.9.2 适配的实现策略 = 新能力特性探测（RPC 可用即显示、不可用即隐藏）+ 升级链路实测（阶段五）。内核 pin 仍保持 2026.8.2 直至阶段五闸门通过。
