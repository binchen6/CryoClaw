# 新功能评估报告

日期：2026-10-14。范围：基于当前代码库既有能力盘点（渠道/模型/技能/插件/记忆/语音/审批/备份/概览/WebBridge/定时任务/工作区 Git/内核与应用双更新链），评估「值得加入」的候选功能。仅评估，不实现。

评估口径：用户价值 × 实现成本 × 与现有架构的契合度。每项给出代码依据（文件级），避免凭印象提案。

## 1. 强推荐（低成本高价值，可在近期版本落地）

### 1.1 全局热键唤起主窗口
- **现状依据**：`src/window.ts:1` 已 `import { globalShortcut }` 但全仓无任何 `globalShortcut.register` 调用——是一个已接线未启用的能力；托盘点击开窗链路（`src/tray.ts` `show()`）可直接复用。
- **价值**：桌面 Agent 类产品的第一高频入口；比「找托盘图标点开」快一个数量级。
- **成本**：低。`globalShortcut.register`（如 `Ctrl+Shift+K`，可配置）+ 外观/高级设置页一个热键录入控件 + 冲突失败的提示文案。退出时 `unregisterAll`。
- **风险**：热键冲突（注册失败要有降级提示）；macOS 权限模型与 Windows 不同需各测一遍。

### 1.2 会话全文搜索
- **现状依据**：侧栏搜索框（`oc-session-panel.ts:487`，`sidebar.searchSessions`）只做标题/预览过滤；内核侧已有 `sqlite-store.worker.mjs`（会话持久化在 SQLite），具备全文检索的存储基础。
- **价值**：会话是用户的核心资产，「我上次让它改的那个正则在哪条会话里」是真实高频痛点。
- **成本**：中。内核若已有消息查询 RPC 则渲染层加一个搜索视图即可；若无则需内核侧加只读查询端点（内核只读约束下需上游配合，或退化为客户端逐会话拉取 + 本地索引，成本高）。**建议先取证内核是否暴露消息查询能力再定档。**
- **风险**：全文索引体积与隐私（消息内容留在本地，符合产品定位）。

### 1.3 技能/插件自动更新（opt-in）
- **现状依据**：本版本已落地手动更新全链路——技能 `skill-store:check-updates` / `skill-store:update`（`src/skill-store.ts`）+ 商店页「更新全部」按钮；插件侧同样有 checkUpdates。自动检查已在进入「已安装」tab 时触发一次。
- **价值**：商店分发的技能/插件是持续演进资产，手动检查依赖用户记得点。
- **成本**：低。设置项（默认关）+ 启动后延迟静默检查 + 有更新时概览页/商店页角标提示（不自动装——安装动作保留给用户，避免供应链静默变更）。
- **风险**：静默升级会改变 Agent 行为，故只做「提示」不做「自动装」是刻意的边界。

### 1.4 定时自动备份（配置层）
- **现状依据**：`src/config-backup.ts` 已有备份写入与「连写 <60s 不新增」去重；`src/settings/backup.ts` 有恢复/导出 UI。缺的是「无人值守的周期快照」。
- **价值**：配置腐败/误删的兜底；与概览页路径卡（备份目录可复制）形成闭环。
- **成本**：低。主进程一个 daily timer（app 运行时检查，错过则启动时补一次）+ 保留策略（如最近 10 份）+ 备份恢复页展示来源（手动/自动）。
- **风险**：注意与现有去重逻辑叠加；备份内容不含明文密钥（现有脱敏约束须延用）。

## 2. 中推荐（战略价值，需排期）

### 2.1 本地模型引导预设（Ollama 等）
- **现状依据**：自定义 provider 流程已完整（`tab-provider.ts` custom baseUrl/apiType + 在线拉模型列表）；Ollama 的 `http://127.0.0.1:11434/v1` 是标准 openai-completions 端点，理论上今天就能配，只是没有引导。
- **价值**：隐私/离线场景入口，扩大产品覆盖面。
- **成本**：中低。预设目录加一项 + 免 key 流程（verify 跳过或探测 `/api/tags`）+ 模型列表自动拉取。
- **风险**：本地模型能力差异大（无 tool-use 的模型会让 Agent 体验塌方），预设引导需要明确的能力提示。

### 2.2 概览页「复制诊断摘要」
- **现状依据**：概览页已聚合版本/资源/网关/路径（`settings:get-env-info` 扩展字段）；诊断导出（`src/diagnostics-export.ts`）产 ZIP 包。
- **价值**：反馈问题时用户常不知道贴什么；一键复制「版本+环境+运行态」脱敏摘要，让 issue 质量翻倍。
- **成本**：低。概览页加一个按钮，拼接现有字段（脱敏：不含 API key/路径中的用户名可选保留）→ 剪贴板。
- **风险**：摘要口径要与 ZIP 诊断包区分（摘要 ≠ 完整日志）。

### 2.3 托盘快捷操作菜单
- **现状依据**：`src/tray.ts` 目前只有「点击开窗」+ 基础菜单。
- **价值**：新会话、最近任务状态、Gateway 重启入口不进主窗口即可达。
- **成本**：中。菜单项 + IPC 转发；任务状态需要渲染层数据回推主进程（或主进程直连 gateway 状态）。
- **风险**：菜单是原生组件，三平台行为差异需逐个验。

## 3. 暂缓 / 不推荐

| 候选 | 结论 | 理由 |
| --- | --- | --- |
| 配置云同步 | 不推荐 | 配置含渠道凭据/API key 哨兵等敏感材料；云同步把攻击面从本机扩到账户体系，与「本地优先」定位冲突 |
| 多 Gateway 并行/配置 profile 切换 | 暂缓 | 单 gateway 架构假设遍布（端口/auth token/状态目录）；收益人群极小 |
| 移动端 App | 不推荐（本仓范围外） | 渠道远程控制（微信/飞书等）已覆盖「手机操控」场景 |
| 内置终端 | 暂缓 | 审批系统 + 工作区已覆盖命令执行路径；内嵌终端是另一个产品 |

## 4. 排期建议

1. 先做 **1.1 全局热键** 与 **2.2 诊断摘要**（合计约 1-2 天，纯本仓改动）；
2. **1.3 自动更新提示** 与 **1.4 定时备份** 随下一版本带上（都有现成底座）；
3. **1.2 会话全文搜索** 先花半天取证内核查询能力再定档；
4. 中推荐项按版本节奏排。
