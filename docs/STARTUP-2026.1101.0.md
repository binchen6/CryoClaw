## 诊断与改动

独立 CPU 分析采样 140.10 s：lstat 自耗时 27.49 s、realpath 17.49 s、open 7.08 s、internalModuleStat 6.97 s、spawn 3.75 s、idle 54.70 s。主要开销来自安全文件检查、插件捕获/物化和原生模块加载。核心解析清单命中 33,011 次，其识别函数仅约 0.244 s inclusive；没有为这个小热点增加补丁。嵌套调用时间不可相加当作可节省时间。

- 保留文件身份、别名/符号链接、来源、插件代次、认证与 SQLite 准入检查。
- 连接准备阶段采用服务端明确给出的重试间隔，普通网络故障保留指数退避，写操作不重放。
- 可见历史优先，每次连接只读一份历史和会话列表；保留重连合并、重置、渐进展示及读取失败提示。
- 渠道库存短生命周期 Node 子进程共享现有网关版本/构建专属 V8 编译缓存。库存到期仍重新执行原生发现，不以编译缓存代替元数据检查。
- 托管 QQ 插件关闭自动版本预热，保留手动查询。该插件未在本轮基线启用，不将它归因为启动主要瓶颈。

### 不修改内核时能调整哪些检查

逐项检查了壳层启动准备：首轮 app-ready 到 gateway spawn 约 4.97 s，后两轮约 0.29/0.33 s；插件镜像对账约 32–40 ms。首次主要是渠道库存缓存未命中，已通过共享编译缓存减少重复编译。更新恢复仅在存在交换日志时执行恢复进程；来源/配置写入相关步骤有先后依赖，不能直接全部 `Promise.all`。原生数据库准备和守护进程清理已有并发，后者另有版本缓存。

检查固定的 OpenClaw 2026.10.9 源码，未发现同时保留相同插件功能、来源准入和方法发布时序的外部并发/延后配置。`SKIP_CHANNELS/PROVIDERS` 会实际关闭渠道，不用于同功能性能比较。壳层重复检查可缓存、非关键版本探测可延后，但当前稳态壳层开销仅约 0.3 s；未为这部分新增调度状态机，也未删除安全检查。主要插件文件成本仍是后续内核侧的独立优化机会。
