## 已关闭的审查缺陷

- 更新等待检查期间退出可能再启动子进程：增加永久退出门闩及 await 后守卫，退出不自动回滚或重启网关。
- 相同 global npmrc 路径内容改变未使依赖缓存失效：加入有效配置内容指纹；无法确认来源时保守重装。
- 高亮代码直接替换 Lit 文本节点可能导致下一次流式渲染抛错/保留旧文本：空代码容器由 ref 独占，更新源文本后重置高亮；异步任务校验源、语言与连接状态。
- Ctrl+N/L 在输入法、按键重复或原生/自定义模态中误触：匹配器与真实 DOM 模态守卫双重覆盖。

## 性能证据与解释

- [前端性能证据](TASK2-FRONTEND-PERFORMANCE.md)：200 份约 50k 字符压力输入，缓存保留约 60M → 1.8M code units；独立 V8 强制 GC 后增量约 60.05MB → 1.83MB。不是应用总内存降幅。
- 相同的 24 个本地 iframe 看板夹具中，滚动热路径主题样式读取、iframe 全量扫描、inspector 消息均为 0；原生嵌套滚动、上下透传及 state roundtrip 通过。原记录 rAF p95 10ms，未测线上 FPS 前后差。
- [构建与更新证据](../../scripts/INSTALLER-PERF-NOTES.md)：有效依赖缓存后单次配对准备阶段 1655 → 20ms；Vite 仍完整执行（2.28 → 2.36s）。不是安装器或整体构建提速百分比。
- 配置快照微基准（226KB，2000 次，5 轮中位数）1206 → 1046ms，约 0.08ms/次；不能解释为启动减少数秒。编译缓存实测更慢，没有启用。
