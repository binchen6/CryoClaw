# 2026.1023.1 · 看板体验、共享输入与性能安全审查

本版承接已发布的 2026.1023.0，保留 OpenClaw 2026.10.6、Node 24.22.1、Electron 43.8.3 与物理网关目录。审查覆盖看板及 SDK、共享输入、任务联动、文件交付边界、诊断日志、依赖打包和 Windows 安装启动。下面区分实现、测量及尚待补充的最终安装验收，不把设计目标当作结果。

## 交互与示例

- 完整参考 167 秒视频的 20 个时间点，采用 CryoClaw 的冰蓝、纸白与深墨视觉。示例从 17 张增至 21 张：保留实时数据、文章画廊、待办习惯、番茄钟、本机数据、音视频与历史内容，新增节奏矩阵、原创环境音、调色间与创作引导。
- 示范是可交互内容：首屏提供只保存到本机的随手记；节奏格子及调色选择可持久保存；声音实验室使用本机 AudioContext 合成原创声景，真实分析音频信号驱动频谱；播放、暂停、选择队列、音量与进度均可操作。不会自动播放或用随机数冒充频谱。
- 第二轮视觉验收将四张章节卡的 ASCII 字符装饰替换为晶体网格 Canvas：固定节点、细线和六边形缓慢漂移，按可见性停帧、减少动态效果时只画稳定帧，位图仅在尺寸或 DPR 变化时重建。顶部提供明确的“让模型制作”入口，不再要求先进入布局编辑模式。
- 固定 1600px 设计画布随应用宽度等比缩放，模块布局不随窄窗重排。新增示例创建副本，已有用户看板和布局不被升级覆盖。
- 看板完整复用对话页输入组件，保留附件、模型、权限、推理、停止与输入法行为。仅在发送时注入封闭的看板目标字段；卡片和示例建议只能填草稿，由用户发送，沿用当前对话。移除输入框重复的白色外层和面向用户的工具协议占位文字。
- 模型选择和思考强度合并为一个双层菜单，不显示模型介绍。保留自定义模型分组、当前未知模型及实际支持的推理级别；右上角快速模式调用原生 `sessions.patch`，显示 `effectiveFastMode`，未操作时保留继承的 auto/ultrafast。失败不会伪装为已保存，迟到响应不会改写后来选中的会话。

## 动效与渲染

- 卡片展开、返回使用可打断的几何过渡；反向操作从当前位置接续，保留 iframe 文档、焦点与卡片状态。共享输入框、模型菜单与推理子页采用短时连续过渡，支持退出和快速反转。
- SDK v2 增加 `motion.frame(draw,{fps})`，默认 30fps，可限制为 1–60fps；不可见、后台或减少动态效果时停止不必要帧。旧 SDK v1 接口继续工作。
- 拖动/缩放通过 rAF 合并，指针结束时提交最后位置。输入和草稿更新保持卡片节点；刷新仅重载当前卡片。Canvas 位图只在尺寸或像素比改变时重建，像素比上限为 2。
- 实测发现声音卡的 CSS 最小内容高度把播放器挤出可见区域，修复网格行及播放器的最小高度，所有控件恢复可操作。菜单连续三次开关曾受异步 toggle 状态影响，改为同步读取原生 popover 状态。
- 置顶窗口上限为 8，已有窗口优先复用。SDK 限制每帧页面 16 个待处理请求、4 个直接数据请求及 32KiB 状态；离开页面清理监听、帧和过渡。

## 插件、技能与任务

- `cryoclaw_dashboard` 增加示例副本、归档与经确认的直接永久删除及模块级刷新；SDK 提供需真实用户操作的 compose/tasks 入口，不在后台自动发送消息或打开操作页。归档和删除都会先暂停同时有明确看板标记、实际关联且仍启用的原生 agentTurn 任务，通用共享任务保留。活动看板删除需 `confirmDelete: true` 和用户确认；归档看板沿用原删除路径。删除后关闭对应置顶窗口；删空后不自动重建示例。
- 内置技能入口保持简短，设计、动效、数据、状态、定时任务和交互细节按需读取 references。工具接口提供结构化契约，不常驻长篇说明。
- 应用数据查询继续作为独立工具提供，普通对话、定时任务和看板均可调用。交付物插件与 MEDIA 文字协议沿用上一版优先级和去重规则，本版通过功能门禁回归。

## 性能与安装

- 看板目录使用 SQLite `PRAGMA data_version` 与 JSON 缓存，外部连接写入会使缓存失效；修改前复制，事务失败使缓存失效，不泄露可变共享对象。
- 同一临时数据库、20 个看板各约 65KB HTML、预热后 1000 次未变化目录读取：旧实现 1356.7ms，新实现 5.7ms。此数值只代表目录轮询，不代表应用启动或全部操作加速比例。证据：`.cache/catalogue-bench-1023-1.json`。
- 同一批 unpacked 文件实测两种差分策略：常规压缩包 391,207,581 B，`store-asar` 404,785,312 B，差 13,577,731 B（约 3.5%）。保留后者，让未变化的 app.asar 区域在后续版本中保持字节一致；不拿不同构建器和可解码格式的旧候选直接估算涨跌。
- 打包仅按 npm 自带 os/cpu 声明移除不兼容目标的包，保留通用或未知包，不跟随链接。不删除当前平台原生依赖。首次对比网关资源净少约 21.1MiB，包含本版新增内容；最终文件量以发布验收记录为准。打包边界排除本地低完整性测试辅助 `node-worktree-low.exe`，避免把约 90MiB 的第二份 Node 误带入安装器；Node、网关与原生依赖不因此删减。
- 保留安装器只清理本安装位置、退出后等待私有 IPC 停机的既有规则。没有扩大卸载对用户工作区或配置的删除范围。宿主停止等待直接由子进程 `exit` 事件落定，不再为每次正常退出追加一个 100ms 轮询周期；Windows 空闲 broker 跳过无资源时的固定回收等待，数据库 clean-close 与有界强制兜底保留。
- 修复旧 ASAR 自动配置残留的失效 vec0 DLL 路径：仅清除缺失且能严格识别为旧受管路径的字段，保留自定义或仍存在的路径及其他内存配置。本机原始 DLL 和安装版 DLL 均实际加载为 sqlite-vec v0.1.9。
- 测试启动失败定位到工作区 Node 的低完整性标签导致临时日志写入被拒绝，进程约 4 秒退出。开发验收使用已安装、相同版本的正常完整性 Node，未修改 ACL 或产品运行时策略。生产启动错误现在区分 spawn、提前退出、日志写入失败和健康检查超时，避免所有失败都报超时。

## 安全与依赖

- 标准安全扫描发现一项低风险 CWE-532：日志可能留下本机卡片能力 URL。统一脱敏 ticket/token、编码键、URL 凭据与 Bearer 等字段，诊断导出同样处理历史日志。保留普通路径与非敏感参数。
- 人工追加修复同 ID 卡片删除重建后旧票据重新生效的问题：每次新建有独立 capabilityId；正常编辑不换身份，删除再创建撤销旧票据。
- 诊断读取改为有界尾部：单文件最多 2MiB、总计最多 8MiB，不再为了几行末尾内容整读大日志。用 64MiB 稀疏文件验证。
- Vite 更新至 7.3.7，Vitest 更新至 4.1.12；根项目与 UI 两棵开发依赖审计均为 0。依据：[Vite 公告](https://github.com/advisories/GHSA-587h-7wmj-h5pm)、[Vitest 公告](https://github.com/advisories/GHSA-qxg6-89mg-rqv8)。
- 网关原生产依赖审计先发现 Undici 三条版本线与 Zod 新公告：根及 OpenClaw 内嵌 Undici 升至 8.12.2，ClawHub 使用 7.30.1，npm 与运行时捆绑副本使用 6.29.1，Zod 升至 4.6.6；npm 12.2.1 与 ip-address 10.7.4 保持。顶层 Undici 8.x 正确满足 proxyline 的 peer，保留内核和 ClawHub 版本。npm/OpenClaw 的 inBundle 文件不只改版本号，按消费者范围校验后同步替换实际字节与锁证据，后续内核更新复用同一策略并在换装前断言。
- 内核更新器独立锁文件也补齐 brace-expansion 5.0.12；根项目、UI、网关、更新器及运行时实际安装树分别审计均为 0，另外枚举发布资源中的相关依赖副本确认实际版本。运行时 npm 保持 11.x，固定为 11.21.1，官方包 SHA512 校验后注入；其 IP parser 更新至 10.7.4，Undici 更新至 6.29.1。运行时的审计使用去除私有 workspaces 声明的临时清单并链接同一安装树，避免公共 registry 查询不存在的 @npmcli/docs；不改生产文件。依据：[npm 11.21.1](https://github.com/npm/cli/releases/tag/v11.21.1)、[npm 12.2.1](https://github.com/npm/cli/releases/tag/v12.2.1)、[IP parser 公告](https://github.com/advisories/GHSA-rxp7-6hxx-x8q5)、[Undici 公告](https://github.com/advisories/GHSA-8436-99hf-9mmv)、[Zod 公告](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)。
- 安全扫描 ID：a7eb8c08-036d-4896-927b-c2a8093520ef。标准扫描针对本项目边界，约 985 文件清单，覆盖部分高风险路径；第三方依赖另外审计。封存报告基于本轮早期快照，不能等同最终源码的穷尽证明。扫描工具返回的线程累计使用量为 input 7,922,780 / cached 7,811,200 / output 20,326 / total 7,943,106；这是线程累计量，不是安全扫描独立消耗。
